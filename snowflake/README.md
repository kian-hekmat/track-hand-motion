# Snowflake

Snowflake holds the pipeline's results and serves the analytical queries and the Tableau views. Two schemas in
`MOTION_INTENT` have the same seven tables (`takes`, `events`, `ground_truth`, `signals`, `frames`, `scores`, `raw_keypoints`):

| Schema | Written by | Takes | Role |
|---|---|---|---|
| `CLOUD` | the Databricks job (`databricks/cloud/m3_publish_snowflake.py`, Spark connector) on every run | vid1-7 | the live data: queries and Tableau views read it |
| `PIPELINE` | the Phase 4 manual load of 2026-10-05 | vid1-5 | the verified reference; each job run compares `CLOUD` against it, row by row |

| File | What it is |
|---|---|
| `11_cloud_setup.sql` | run once as ACCOUNTADMIN: creates `CLOUD` and the role `DATABRICKS_PIPELINE_ROLE`, which can write only to `CLOUD` and read `PIPELINE`, and gives it to the key-pair user `DATABRICKS_SVC` |
| `05_tableau_views.sql` | the three Tableau views (`v_tableau_phases`, `v_tableau_signals`, `v_tableau_accuracy`); the job creates them in `CLOUD` |
| `../queries.sql` | five analytical queries (average event duration by kind, most ambiguous takes, time between reaches with `LAG`, phase transitions with `LEAD`, agreement with the hand labels per phase) |

## Checked inside Snowflake on every job run

The M3 notebook connects with the Python connector and runs SQL generated by `src/cloud/snowflake_sql.py`:
- the row count of each `CLOUD` table equals what Databricks wrote in that run (`CLOUD.PUBLISH_RUNS`);
- every `PIPELINE` row has a `CLOUD` row with the same key and equal values, column by column (decimals within the stated
  tolerances, everything else exact);
- the three Tableau views build on `CLOUD` with the expected row counts (295, 5,659, 7);
- each query in `queries.sql`, unchanged, returns the same rows for vid1-5 in both schemas.

Latest result: all 31 checks passed in job run 121730247088002 (2026-10-08). Evidence and history:
`../databricks/cloud/README.md` (M3, M4).

## Getting the data into Tableau

Tableau Public cannot connect to Snowflake, so the three views are downloaded as CSV from Snowsight and checked with
`python scripts/check_cloud_tableau_exports.py` before they go into the workbook. Steps: `../tableau/README.md`.

## Phase 4 (how `PIPELINE` was made)

On 2026-10-05 the verified export (`data/export/`) was staged and loaded with `COPY INTO`; 46 of 46 row-count and integrity
checks passed, and the five queries matched local DuckDB results and an independent pandas recomputation. The person who
watched the videos confirmed the query answers against them (a verbal sign-off; the filled-in checklist was not saved).

The load and verification scripts were retired in the cloud cleanup and are kept at the git tag `pre-cloud-cleanup`
(`snowflake/01_setup.sql` to `04_fingerprint.sql`, `scripts/build_snowflake_scripts.py`). They are what would rebuild `PIPELINE`
if the trial account is replaced. Without `PIPELINE`, the job's in-Snowflake comparison has no reference, though the comparison
with the verified export files in Databricks still runs.
